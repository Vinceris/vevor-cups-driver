# vevor-cups-driver

Open-source, native Apple Silicon CUPS driver for the **VEVOR Y486 / Y486BT**
4×6" thermal label printers (and other TSPL printers built on the same OEM
engine, USB vendor id `0x5958`).

The driver VEVOR ships for macOS is an **x86_64-only** binary. macOS 27 does
not carry Rosetta 2 across an upgrade, so on an Apple Silicon Mac the vendor
filter dies with `Bad CPU type in executable`, the printer stops working, and
the vendor's `LaunchVevor` helper daemon crash-loops every 10 seconds
(which in turn makes the Dock and Control Center reload their login-item
data every 10 seconds). This project replaces the whole package with:

- `rastertovevor` – a small, universal (arm64 + x86_64) CUPS raster→TSPL
  filter that produces **the same byte stream** as the vendor filter;
- two PPDs (203 dpi and 300 dpi) using the same option keywords as the
  vendor PPDs, so an existing queue keeps its settings;
- an installer that re-points existing queues, and an uninstaller for the
  vendor package.

No auto-add daemon: add the queue once and it stays.

## Status

| | |
|---|---|
| Filter output vs. vendor filter | matches the vendor's TSPL sequence, reconstructed instruction-by-instruction from the vendor binary (see below); 25 offline tests, plus a PDF → CUPS → TSPL pipeline test |
| Hardware test on a Y486 | **pending** – please open an issue with your result |
| macOS | 12+ (built with `-mmacosx-version-min=11`); developed on macOS 27 |
| Linux | builds with `libcups2-dev` / `libcupsimage2-dev`; untested |

## Install (macOS)

```sh
git clone https://github.com/mattiacolombomc/vevor-cups-driver.git
cd vevor-cups-driver
make test                 # optional: builds and runs the offline tests
sudo ./install.sh         # installs filter + PPDs, re-points vendor queues
sudo ./uninstall-vendor.sh   # optional: removes the vendor package + daemon
```

If you have no queue yet, plug the printer in and run
`sudo ./install.sh --add VEVOR_Y486` (add `--300dpi` for a 300 dpi model),
or add it from *System Settings → Printers* choosing the
"VEVOR Label Printer 203 dpi Open" driver.

Print a label:

```sh
lp -d VEVOR_Y486 -o media=w283h425 label.pdf      # 100 x 150 mm
```

Options (`-o key=value`, also in the print dialog):

| Option | Values | TSPL |
|---|---|---|
| `Darkness` | `Default`, `0`…`15` | `DENSITY n` (omitted for Default) |
| `zePrintRate` | `Default`, `1`…`8` in/s | `SPEED n` (1 is sent as 2, like the vendor) |
| `zeMediaTracking` | `Gap`, `BLine`, `Continuous` | `GAP g mm,o mm` / `BLINE g mm,o mm` / `GAP 0 mm,0 mm` |
| `GapOrMarkHeight`, `GapOrMarkOffset` | `0`…`10` mm | the `g` and `o` above |
| `AdjustHoriaontal` (sic), `AdjustVertical` | `-20`…`20` mm | `REFERENCE x,y` in dots |
| `Rotate` | `0`, `1` (180°), `2` (90°), `3` (270°) | bitmap rotated in software |
| `AutoDotted` | `0`, `1` | `SETC AUTODOTTED OFF/ON` |
| `media` | any `PageSize` in the PPD, or `Custom.WIDTHxHEIGHT` | `SIZE w mm,h mm` |

## What the filter sends

```
<200 × 0x00>                    wake-up padding
SIZE 100 mm,150 mm              ceil(dots / dots-per-mm); 8 dots/mm at 203 dpi, 12 at 300 dpi
REFERENCE 0,0
GAP 3 mm,0 mm
DENSITY 8
SPEED 4
SETC AUTODOTTED OFF
SETC PAUSEKEY ON
SETC WATERMARK OFF
CLS
BITMAP 0,0,100,1198,1,<1-bpp rows, 0 bit = dot>
PRINT 1,1
```

Every line ends in `\r\n`; a `\n` separates the bitmap from `PRINT`. A grey
value ≤ 200 (0 = black, 255 = white) becomes a dot. Copies are handled by
CUPS (`cupsManualCopies`), one `PRINT 1,1` per page.

## How it was made

The vendor filter `/Library/Printers/VevorPrinter/Filter/rastertolabel`
(package `com.mygreatcompany.pkg.VevorPrinter` 1.5.8, 2022) is the CUPS
`rastertolabel` filter (Apache-2.0) with an extra model number `20` for
TSPL, plus a few unused image-processing helpers. This implementation was
written from the disassembly of that binary (`otool -tV`), keeping only the
TSPL path, and cross-checked against the
[`beeprt` branch of proski/cups](https://github.com/proski/cups/blob/beeprt/filter/rastertolabel.c),
which adds the same OEM family to upstream CUPS. Differences to the vendor
filter, on purpose:

- no check that the queue's device URI contains `//VEVOR` and `/Y486`
  (the vendor filter refuses any other queue with "No Available Printer");
- no `LaunchVevor` daemon (auto-creating the queue by polling `system_profiler`);
- runs without a PPD too, reading the same option keywords from the job;
- accepts 1-bit and RGB rasters in addition to 8-bit grey.

`tests/diff-vs-vendor.sh` runs both filters on the same rasters and
compares the output byte-for-byte; it needs Rosetta 2 and the vendor
package still installed.

## Layout

```
src/rastertovevor.c     the filter
ppd/*.ppd               generated by tools/gen_ppd.py (make ppd)
tests/                  mkras.c (synthetic rasters), test_filter.py, diff-vs-vendor.sh
install.sh              macOS installer (sudo)
uninstall.sh            remove this driver
uninstall-vendor.sh     remove the VEVOR package and its LaunchDaemon (backs files up)
```
